    ⚠️ نقاط تحتاج تحسين¶

    المشكلة الموقع التأثير
    بعض الشاشات تعتمد على API مباشرة fields_api.dart يفشل Offline
    لا يوجد Bridge Layer رسمي - التحليل يصل مباشرة للمستخدم
    تصنيف الخدمات غير واضح docker-compose.yml صعوبة في الأولويات

    2️⃣ تقييم نقدي للميثاق المقترح¶

    ✅ ما هو صحيح 100%:¶

    1. مبدأ "الميدان أولاً"
    2. المزارع يعمل في بيئة ضعيفة الاتصال
    3. القرارات يجب أن تكون قابلة للتنفيذ فوراً

    4. التحليل المعقد لا قيمة له إذا لم يُترجم لفعل

    5. فصل الطبقات الثلاث

    Field Layer → Bridge Layer → Analysis Layer

    • هذا نموذج معماري سليم ومثبت

    • قاعدة "لا Runtime Dependency على التحليل"

    • هذا موجود جزئياً في الكود (SyncEngine)
    • يحتاج تطبيق أشمل

    ⚠️ ما يحتاج تعديل:¶

    1. تصنيف الخدمات غير دقيق بالكامل
    الخدمة التصنيف المقترح التصنيف الصحيح السبب
    billing-core غير مذكور Field-Critical الاشتراك يؤثر على الوصول
    weather-advanced Analysis Bridge + Analysis التنبؤات القصيرة ميدانية
    notification-service Bridge ✅ صحيح -
    astronomical-calendar غير مذكور Field-Critical التوقيت الزراعي اليمني
    1. غياب طبقة الأمان في النموذج
    2. الميثاق لم يذكر auth-service

    3. JWT offline capabilities مهمة جداً

    4. IoT غير مصنف

    5. iot-service يجب أن يكون Bridge
    6. البيانات تأتي من الحقل مباشرة

    4️⃣ تحليل الكود الحالي¶

    SyncEngine - تطبيق ممتاز للـ Offline-First¶

    // apps/mobile/lib/core/sync/sync_engine.dart

/// ✅ صحيح: Outbox Pattern
Future<SyncResult> runOnce() async {
  // 1. Process outbox (upload local changes)
  final uploadResult = await _processOutbox();

  // 2. Pull latest data from server
  final pullResult = await _pullFromServer();

  // 3. Cleanup completed outbox items
  await database.cleanupOutbox();
}

/// ✅ صحيح: Network-aware sync
_networkStatus.onlineStream.listen((online) {
  if (online) {
    print('📶 Network restored - triggering sync');
    runOnce();
  }
});

    التقييم: الكود الحالي يطبق الميثاق جزئياً ✅

    5️⃣ الفجوات التي يجب سدها¶

    Gap 1: Bridge Layer غير موجود رسمياً¶

    الحالي:

    Analysis Service → API → Mobile

    المطلوب:

    Analysis Service → Bridge Service → Task/Alert → Mobile

    Gap 2: تصنيف الأولويات في docker-compose¶

    الحالي: جميع الخدمات بنفس الأولوية

    المطلوب:

    # docker-compose.yml
services:
  # Priority 1: Field-Critical
  field-service:
    deploy:
      restart_policy:
        condition: always

  # Priority 2: Bridge
  indicators-service:
    deploy:
      restart_policy:
        condition: on-failure

  # Priority 3: Analysis
  crop-health-ai:
    deploy:
      restart_policy:
        condition: on-failure
