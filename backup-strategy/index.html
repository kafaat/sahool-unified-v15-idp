    نظرة عامة¶

    الأهداف الرئيسية¶

    تهدف استراتيجية النسخ الاحتياطي لمنصة سهول إلى:

    • حماية البيانات: ضمان عدم فقدان البيانات الحرجة
    • التعافي السريع: تقليل وقت التعطل (RTO < 4 ساعات)
    • نقطة استعادة دقيقة: الحد الأدنى لفقدان البيانات (RPO < 1 ساعة)
    • الامتثال: الالتزام بمتطلبات حماية البيانات
    • الاختبار المنتظم: التحقق من صحة النسخ الاحتياطي شهريًا

    المكونات المشمولة في النسخ الاحتياطي¶

    المكون النوع الأولوية التكرار
    PostgreSQL (PostGIS) قاعدة بيانات حرج يومي، أسبوعي، شهري
    Redis ذاكرة التخزين المؤقت عالي يومي
    MinIO/S3 تخزين الملفات حرج يومي
    NATS JetStream قائمة الرسائل متوسط يومي
    ملفات الإعدادات تكوين عالي عند كل تغيير

    معايير الأداء¶

    • RTO (Recovery Time Objective): 4 ساعات
    • RPO (Recovery Point Objective): 1 ساعة
    • نسبة نجاح النسخ الاحتياطي: > 99.9%
    • وقت التحقق: < 30 دقيقة

    استراتيجية النسخ الاحتياطي لـ PostgreSQL¶

    1. طرق النسخ الاحتياطي¶

    أ. النسخ الاحتياطي المنطقي (Logical Backup)¶

    الأداة: pg_dump / pg_dumpall

    المزايا:

    • سهولة الاستعادة الجزئية
    • نقل البيانات بين إصدارات PostgreSQL مختلفة
    • قابلية للقراءة والتعديل (SQL format)

    الاستخدام:

    # نسخ احتياطي كامل بصيغة مخصصة (موصى به)
pg_dump -h postgres -U sahool -F c -f sahool_backup.dump sahool

# نسخ احتياطي بصيغة SQL نصية
pg_dump -h postgres -U sahool -f sahool_backup.sql sahool

# نسخ احتياطي لجميع قواعد البيانات
pg_dumpall -h postgres -U sahool -f all_databases.sql

    الجدول الزمني:

    • يومي: الساعة 2:00 صباحًا
    • أسبوعي: الأحد 3:00 صباحًا
    • شهري: أول يوم من الشهر 4:00 صباحًا

    ب. النسخ الاحتياطي الفيزيائي (Physical Backup)¶

    الأداة: pg_basebackup

    المزايا:

    • استعادة أسرع
    • نسخ احتياطي على مستوى الملفات
    • دعم Point-in-Time Recovery (PITR)

    الاستخدام:

    # نسخ احتياطي أساسي
pg_basebackup -h postgres -U sahool -D /backups/base -F tar -z -P

# نسخ احتياطي مع WAL
pg_basebackup -h postgres -U sahool -D /backups/base -X stream -P

    الجدول الزمني:

    • أسبوعي: السبت 1:00 صباحًا

    2. تكوين PostgreSQL للنسخ الاحتياطي¶

    -- تفعيل WAL archiving
ALTER SYSTEM SET wal_level = 'replica';
ALTER SYSTEM SET archive_mode = 'on';
ALTER SYSTEM SET archive_command = 'cp %p /var/lib/postgresql/wal_archive/%f';
ALTER SYSTEM SET max_wal_senders = 3;

-- إعادة تحميل الإعدادات
SELECT pg_reload_conf();

    3. الضغط والتشفير¶

    # ضغط مع gzip
pg_dump -h postgres -U sahool sahool | gzip > backup.sql.gz

# تشفير مع OpenSSL
pg_dump -h postgres -U sahool sahool | \
  openssl enc -aes-256-cbc -salt -pbkdf2 -out backup.sql.enc

# ضغط وتشفير معًا
pg_dump -h postgres -U sahool sahool | \
  gzip | \
  openssl enc -aes-256-cbc -salt -pbkdf2 -out backup.sql.gz.enc

    4. سياسة الاحتفاظ¶

    نوع النسخة مدة الاحتفاظ عدد النسخ
    يومي 7 أيام 7 نسخ
    أسبوعي 4 أسابيع 4 نسخ
    شهري 12 شهر 12 نسخة
    سنوي 5 سنوات 5 نسخ

    5. التحقق من صحة النسخة¶

    # التحقق من النسخة المضغوطة
pg_restore --list backup.dump | head -20

# اختبار الاستعادة في قاعدة بيانات تجريبية
pg_restore -h postgres -U sahool -d sahool_test backup.dump --verbose

    استراتيجية النسخ الاحتياطي لـ Redis¶

    1. طرق النسخ الاحتياطي¶

    أ. RDB (Redis Database Backup)¶

    آلية العمل: لقطة (snapshot) ثنائية للبيانات

    التكوين في redis.conf:

    # حفظ تلقائي
save 900 1      # بعد 900 ثانية إذا تغير مفتاح واحد على الأقل
save 300 10     # بعد 300 ثانية إذا تغيرت 10 مفاتيح
save 60 10000   # بعد 60 ثانية إذا تغيرت 10000 مفتاح

# اسم الملف
dbfilename dump.rdb

# المسار
dir /data

# الضغط
rdbcompression yes

# التحقق من التجزئة
rdbchecksum yes

    النسخ الاحتياطي اليدوي:

    # حفظ فوري (يعلق العمليات)
redis-cli -a $REDIS_PASSWORD SAVE

# حفظ في الخلفية (موصى به)
redis-cli -a $REDIS_PASSWORD BGSAVE

# نسخ الملف
docker exec sahool-redis redis-cli -a $REDIS_PASSWORD BGSAVE
sleep 5
docker cp sahool-redis:/data/dump.rdb /backups/redis/dump_$(date +%Y%m%d).rdb

    ب. AOF (Append Only File)¶

    التكوين:

    # تفعيل AOF
appendonly yes
appendfilename "appendonly.aof"

# استراتيجية المزامنة
appendfsync everysec  # توازن بين الأداء والأمان

# إعادة الكتابة التلقائية
auto-aof-rewrite-percentage 100
auto-aof-rewrite-min-size 64mb

    النسخ الاحتياطي:

    # إعادة كتابة AOF
redis-cli -a $REDIS_PASSWORD BGREWRITEAOF

# نسخ الملف
docker cp sahool-redis:/data/appendonly.aof /backups/redis/

    2. استراتيجية النسخ الاحتياطي الموصى بها¶

    النهج المختلط:

    • استخدام RDB للنسخ الاحتياطي اليومي (سريع، حجم أصغر)
    • استخدام AOF للتعافي من الفشل (بيانات أحدث، RPO أقل)

    3. الجدول الزمني¶

    # يومي: RDB snapshot
0 2 * * * /scripts/backup/backup_redis.sh daily

# أسبوعي: نسخ كامل مع AOF
0 3 * * 0 /scripts/backup/backup_redis.sh weekly

    4. سياسة الاحتفاظ¶

    نوع النسخة مدة الاحتفاظ
    يومي (RDB) 7 أيام
    أسبوعي (RDB+AOF) 4 أسابيع

    5. التحقق¶

    # فحص ملف RDB
redis-check-rdb /backups/redis/dump.rdb

# فحص ملف AOF
redis-check-aof /backups/redis/appendonly.aof

# فحص بالاستعادة في بيئة منفصلة
docker run --rm -v /backups/redis:/data redis:7-alpine \
  redis-server --appendonly no --save ""

    استراتيجية النسخ الاحتياطي لـ MinIO / S3¶

    1. طرق النسخ الاحتياطي¶

    أ. النسخ المتطابق (Mirror)¶

    الأداة: mc mirror

    # نسخ متطابق إلى موقع خارجي
mc mirror --overwrite sahool/uploads s3-backup/sahool-uploads

# نسخ متطابق مع الحذف
mc mirror --overwrite --remove sahool/uploads s3-backup/sahool-uploads

    ب. النسخ المتزايد (Incremental)¶

    # نسخ الملفات الجديدة والمحدثة فقط
mc mirror --newer-than 24h sahool/uploads s3-backup/sahool-uploads-daily

    ج. لقطة كاملة (Snapshot)¶

    # نسخ كامل بالتاريخ
BACKUP_DATE=$(date +%Y%m%d)
mc mirror sahool/uploads s3-backup/snapshots/${BACKUP_DATE}/uploads

    2. استراتيجية التخزين متعدد المناطق¶

    # إعداد مواقع متعددة
mc alias set primary http://minio-primary:9000 ACCESS_KEY SECRET_KEY
mc alias set backup http://minio-backup:9000 ACCESS_KEY SECRET_KEY
mc alias set aws-s3 https://s3.amazonaws.com ACCESS_KEY SECRET_KEY

# نسخ احتياطي متعدد المستويات
mc mirror primary/uploads backup/uploads              # محلي
mc mirror primary/uploads aws-s3/sahool-backup/uploads  # سحابي

    3. إصدارات الكائنات (Versioning)¶

    # تفعيل الإصدارات
mc version enable sahool/uploads

# عرض الإصدارات
mc ls --versions sahool/uploads/file.pdf

# استعادة إصدار قديم
mc cp --version-id VERSION_ID sahool/uploads/file.pdf restored-file.pdf

    4. سياسة دورة الحياة (Lifecycle)¶

    # إنشاء سياسة دورة الحياة
cat > lifecycle.json <<EOF
{
  "Rules": [
    {
      "ID": "DeleteOldVersions",
      "Status": "Enabled",
      "NoncurrentVersionExpiration": {
        "NoncurrentDays": 90
      }
    },
    {
      "ID": "MoveToGlacier",
      "Status": "Enabled",
      "Transition": {
        "Days": 30,
        "StorageClass": "GLACIER"
      }
    }
  ]
}
EOF

# تطبيق السياسة
mc ilm import sahool/uploads < lifecycle.json

    5. الجدول الزمني¶

    نوع النسخة التكرار الوقت الوجهة
    متزايد يومي 1:00 صباحًا MinIO محلي
    لقطة كاملة أسبوعي الأحد 2:00 صباحًا MinIO محلي + S3
    أرشيف شهري أول يوم 3:00 صباحًا S3 Glacier

    6. سياسة الاحتفاظ¶

    # حذف النسخ القديمة تلقائيًا
mc rm --recursive --force --older-than 30d backup/daily/
mc rm --recursive --force --older-than 90d backup/weekly/

    7. التحقق من السلامة¶

    # فحص تكامل الملفات
mc admin heal sahool

# مقارنة البيانات
mc diff sahool/uploads s3-backup/uploads

# التحقق من الحجم
mc du sahool/uploads
mc du s3-backup/uploads

    # ═══════════════════════════════════════════════════════════════════════
# SAHOOL Platform Backup Schedule - جدول النسخ الاحتياطي لمنصة سهول
# ═══════════════════════════════════════════════════════════════════════

SHELL=/bin/bash
PATH=/usr/local/bin:/usr/bin:/bin
MAILTO=admin@sahool.com

# ───────────────────────────────────────────────────────────────────────
# Daily Backups - النسخ الاحتياطي اليومي
# ───────────────────────────────────────────────────────────────────────

# MinIO - كل يوم الساعة 1:00 صباحًا
0 1 * * * /scripts/backup/backup_minio.sh daily >> /var/log/backup/minio.log 2>&1

# PostgreSQL - كل يوم الساعة 2:00 صباحًا
0 2 * * * /scripts/backup/backup_postgres.sh daily >> /var/log/backup/postgres.log 2>&1

# Redis - كل يوم الساعة 2:15 صباحًا
15 2 * * * /scripts/backup/backup_redis.sh daily >> /var/log/backup/redis.log 2>&1

# NATS - كل يوم الساعة 2:30 صباحًا
30 2 * * * /scripts/backup/backup_nats.sh daily >> /var/log/backup/nats.log 2>&1

# ───────────────────────────────────────────────────────────────────────
# Weekly Backups - النسخ الاحتياطي الأسبوعي
# ───────────────────────────────────────────────────────────────────────

# MinIO - كل أحد الساعة 2:00 صباحًا
0 2 * * 0 /scripts/backup/backup_minio.sh weekly >> /var/log/backup/minio.log 2>&1

# PostgreSQL - كل أحد الساعة 3:00 صباحًا
0 3 * * 0 /scripts/backup/backup_postgres.sh weekly >> /var/log/backup/postgres.log 2>&1

# Redis - كل أحد الساعة 3:15 صباحًا
15 3 * * 0 /scripts/backup/backup_redis.sh weekly >> /var/log/backup/redis.log 2>&1

# Backup All - كل أحد الساعة 4:00 صباحًا (نسخة شاملة)
0 4 * * 0 /scripts/backup/backup_all.sh weekly >> /var/log/backup/all.log 2>&1

# ───────────────────────────────────────────────────────────────────────
# Monthly Backups - النسخ الاحتياطي الشهري
# ───────────────────────────────────────────────────────────────────────

# All services - أول يوم من الشهر الساعة 3:00 صباحًا
0 3 1 * * /scripts/backup/backup_all.sh monthly >> /var/log/backup/all.log 2>&1

# ───────────────────────────────────────────────────────────────────────
# Maintenance Tasks - مهام الصيانة
# ───────────────────────────────────────────────────────────────────────

# Cleanup old backups - كل يوم الساعة 5:00 صباحًا
0 5 * * * /scripts/backup/cleanup.sh >> /var/log/backup/cleanup.log 2>&1

# Verify backups - كل يوم الساعة 6:00 صباحًا
0 6 * * * /scripts/backup/verify-backup.sh >> /var/log/backup/verify.log 2>&1

# Generate backup report - كل اثنين الساعة 8:00 صباحًا
0 8 * * 1 /scripts/backup/generate_report.sh >> /var/log/backup/report.log 2>&1

    إجراءات الاستعادة¶

    1. استعادة PostgreSQL¶

    أ. استعادة كاملة من pg_dump¶

    #!/bin/bash
# استعادة قاعدة بيانات PostgreSQL

BACKUP_FILE="/backups/postgres/sahool_20250127_020000.dump"

# 1. إيقاف الخدمات المعتمدة
docker compose stop api-gateway auth-service

# 2. إسقاط قاعدة البيانات الحالية (حذر!)
docker exec -it sahool-postgres psql -U sahool -c "DROP DATABASE IF EXISTS sahool;"

# 3. إنشاء قاعدة بيانات جديدة
docker exec -it sahool-postgres psql -U sahool -c "CREATE DATABASE sahool;"

# 4. استعادة البيانات
docker exec -i sahool-postgres pg_restore \
  -U sahool \
  -d sahool \
  -v \
  --no-owner \
  --no-privileges \
  < "${BACKUP_FILE}"

# 5. إعادة بناء الفهارس
docker exec -it sahool-postgres psql -U sahool -d sahool -c "REINDEX DATABASE sahool;"

# 6. تحديث الإحصائيات
docker exec -it sahool-postgres psql -U sahool -d sahool -c "ANALYZE;"

# 7. إعادة تشغيل الخدمات
docker compose start api-gateway auth-service

echo "✓ تمت استعادة قاعدة البيانات بنجاح"

    ب. استعادة جزئية (جدول واحد)¶

    # استعادة جدول واحد
pg_restore -U sahool -d sahool -t users backup.dump

# استعادة مخطط محدد
pg_restore -U sahool -d sahool -n public backup.dump

    ج. Point-in-Time Recovery (PITR)¶

    # 1. استعادة النسخة الأساسية
tar -xzf base_backup.tar.gz -C /var/lib/postgresql/data

# 2. إنشاء ملف recovery.conf
cat > /var/lib/postgresql/data/recovery.conf <<EOF
restore_command = 'cp /var/lib/postgresql/wal_archive/%f %p'
recovery_target_time = '2025-01-27 14:30:00'
recovery_target_action = 'promote'
EOF

# 3. إعادة تشغيل PostgreSQL
docker compose restart postgres

    2. استعادة Redis¶

    أ. استعادة من RDB¶

    #!/bin/bash
# استعادة Redis من RDB

BACKUP_FILE="/backups/redis/dump_20250127.rdb"

# 1. إيقاف Redis
docker compose stop redis

# 2. نسخ ملف RDB
docker cp "${BACKUP_FILE}" sahool-redis:/data/dump.rdb

# 3. تعيين الصلاحيات
docker exec sahool-redis chown redis:redis /data/dump.rdb

# 4. إعادة تشغيل Redis
docker compose start redis

# 5. التحقق
sleep 5
docker exec sahool-redis redis-cli -a $REDIS_PASSWORD DBSIZE

echo "✓ تمت استعادة Redis بنجاح"

    ب. استعادة من AOF¶

    # 1. إيقاف Redis
docker compose stop redis

# 2. نسخ ملف AOF
docker cp /backups/redis/appendonly.aof sahool-redis:/data/

# 3. إعادة تشغيل مع تفعيل AOF
docker compose start redis

# 4. إعادة بناء RDB من AOF
docker exec sahool-redis redis-cli -a $REDIS_PASSWORD BGREWRITEAOF

    3. استعادة MinIO¶

    أ. استعادة كاملة¶

    #!/bin/bash
# استعادة MinIO من نسخة احتياطية

SOURCE_ALIAS="backup"
TARGET_ALIAS="sahool"
BUCKET="uploads"

# 1. حذف البيانات الحالية (اختياري)
mc rm --recursive --force ${TARGET_ALIAS}/${BUCKET}/

# 2. استعادة من النسخة الاحتياطية
mc mirror --overwrite ${SOURCE_ALIAS}/${BUCKET} ${TARGET_ALIAS}/${BUCKET}

# 3. التحقق
mc ls ${TARGET_ALIAS}/${BUCKET}

echo "✓ تمت استعادة MinIO بنجاح"

    ب. استعادة ملف محدد¶

    # استعادة ملف واحد
mc cp backup/uploads/important-file.pdf sahool/uploads/

# استعادة مجلد محدد
mc mirror backup/uploads/documents/ sahool/uploads/documents/

    ج. استعادة إصدار قديم¶

    # عرض الإصدارات
mc ls --versions sahool/uploads/document.pdf

# استعادة إصدار محدد
VERSION_ID="xxxxx-xxxxx-xxxxx"
mc cp --version-id ${VERSION_ID} \
  sahool/uploads/document.pdf \
  sahool/uploads/document_restored.pdf

    4. خطة التعافي الكامل من الكوارث¶

    المرحلة 1: التقييم (0-15 دقيقة)¶

    # 1. تقييم مدى الضرر
/scripts/disaster-recovery/assess.sh

# 2. تحديد آخر نسخة احتياطية صالحة
/scripts/disaster-recovery/find-latest-backup.sh

# 3. إشعار الفريق
/scripts/disaster-recovery/notify-team.sh

    المرحلة 2: التحضير (15-30 دقيقة)¶

    # 1. إيقاف جميع الخدمات
docker compose down

# 2. نسخ احتياطي للحالة الحالية (للتحليل)

    أ. تشفير النسخ الاحتياطية¶

    #!/bin/bash
# تشفير النسخة الاحتياطية باستخدام GPG

BACKUP_FILE="sahool_backup.sql"

# تشفير

# فك التشفير
