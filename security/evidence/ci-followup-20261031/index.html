    CI follow-up after the shared PyJWT repair — 2026-10-31¶

    Scope¶

    This independent change starts from main at 52041a321868c4c71633a149f596f91bd569307c, after PyJWT PR #1995 was merged and its dedicated Python 3.11/3.12 acceptance passed. It repairs demonstrated CI checkout, monitoring, import-isolation, and test-result reporting defects. Dependency manifests, Python support policy, constraints, and uv.lock are unchanged. Product authentication and LLM provider code are unchanged.

    Defects and repairs¶

    Scorecard checkout¶

    The repository tracked 38 mode-160000 entries under .claude/worktrees/agent-* without a .gitmodules file. These point to seven historical commits of this same repository, rather than declared external dependencies. Recursive Git credential cleanup therefore failed before Scorecard analysis started.

    The repair removes exactly those tracked references with git rm --cached; all local directories and their contents were preserved. It adds a root-scoped ignore rule and a Governance Structure Guard check that rejects future tracked local worktrees, including forced additions. Normal Claude configuration and legitimate declared submodules elsewhere remain supported.

    The Scorecard workflow, persist-credentials: false, analysis, publication, and SARIF upload are unchanged. Baseline recursive traversal exits 128; the corrected index exits 0. Actual Scorecard acceptance requires a successful main-branch analysis and upload: its upstream publisher requires the default branch for published results. A branch-only dispatch is not a substitute.

    PR Status Monitor¶

    The read-only gh pr list request previously failed immediately on HTTP 502 or truncated JSON. A standard-library helper now makes at most three attempts, each limited to 60 seconds, with two- and four-second retry delays. It validates the response before atomically publishing the snapshot. Exhaustion fails; it never substitutes an empty list for an API failure. The explicit 1000-PR limit replaces the CLI's default 30-item limit, and reaching that limit fails because completeness cannot be established.

    The status-count expression also had an independently reproduced jq error: it applied .conclusion to an entire array. The corrected expression iterates checks and counts failing PRs once, including legacy FAILURE/ERROR status contexts. Reports describe technical mergeability without claiming merge readiness or subtracting overlapping failure categories. Existing notification and branch-update jobs, conditions, permissions, and triggers are unchanged.

    Import isolation and Quality Gate¶

    The smoke import test deleted live modules from sys.modules. Unit tests collected earlier retained functions from the old module while their mocks targeted the new module. The two LLM convenience tests then attempted Ollama.

    Fresh imports now run in a separate interpreter with a 30-second timeout and a required completion record. The existing optional-ImportError skip policy is retained; circular imports, runtime failures, timeouts, and missing reports fail. The parent interpreter's module identities remain intact.

    The Quality Gate now records both pytest and tee exit codes, uploads logs, JUnit, and coverage evidence, then enforces the test result. The aggregate also fails when the test job failed, was skipped, or lacks successful evidence. A security warning cannot overwrite a blocking report. This change enforces test execution and its evidence; it does not redesign the policies of the other quality stages.

    Commands, source hashes, negative controls, skip reasons, tool identity, and validation summaries are recorded in verification.json.

    Existing separate work¶

    • Flutter 3.27.1 pins intl 0.19.0, while the mobile manifest requires intl ^0.20.2. The same dependency-resolution failure exists before and after PR #1995; no Flutter SDK or dependency decision is included here.
    • Root uv.lock still contains PyJWT 2.11.0 and its TensorFlow/NumPy/Python resolver conflict remains separate. No frozen-lock repair is claimed.
    • The existing python-multipart security findings are unchanged.
    • The push-only Dependency Vulnerability Scan still fails its CRITICAL gate: the PyJWT merge reports 26 findings, compared with 28 on the exact earlier baseline. The workflow is unchanged. Counts alone do not prove which advisories remain, and this CI repair does not relax that gate.
    • Other masked service, contract, and security checks are not certified as successful by this repair. No deployment acceptance is claimed.
