    JavaScript critical dependency security — 2026-10-31¶

    This evidence records the JavaScript dependency repair based on commit ab53c98596daca1740d2ac5a5dbd48db7b24e34f. The repair removes the 16 JavaScript CRITICAL findings in the reproduced Trivy baseline and the remaining CRITICAL entries found by the final npm audit. It does not make the whole dependency tree or every application test suite clean.

    The complete results and provenance are in verification.json. source-manifest.json identifies the reviewed source bytes, including manifests, locks, consumers, tests, and workflow. Documentation and generated build output are excluded from that source snapshot. This evidence was prepared before the publishing commit; the source hashes, rather than an invented final commit ID, identify the candidate.

    The existing local shared-events consumers in chat-service and field-management-service use the workspace package path. Their Dockerfiles already translate that path for their build contexts.     Storybook compiler selection¶

    Both the preserved baseline (Next 15.5.14 / Storybook 8.6.18) and the candidate (Next 15.5.28 / Storybook 8.6.19) initially failed. The first cause was external Webpack 5.105.4's DefinePlugin requesting collectDestructuringAssignmentProperties from Next's bundled Webpack 5.98.0 parser, which lacks that hook. The later shutdown tap stack was not the cause.

    apps/admin/.storybook/main.ts sets NEXT_PRIVATE_LOCAL_WEBPACK=true while loading Storybook configuration so its compiler and plugins use the same installed Webpack. No global environment, production Next.js script, or dependency policy was changed. The final build launched with no inherited flag, used no diagnostic preload, and produced 16 stories plus 3 documentation entries. Baseline diagnosis reused the preserved old installation, so it is not presented as a fresh baseline npm ci. Asset-size and react-leaflet metadata warnings remain in the successful build.

    Reports survive Playwright¶

The actual rerun recorded identical before/after hashes for the npm audit, Node JUnit, shared-hooks JUnit, and shared-ui JUnit. The new browser JUnit also exists and matches its recorded hash. See browser-evidence-preservation.json. This verifies that Playwright no longer removes the preceding security evidence.

    Reproduction and evidence integrity¶

    Use the checked-in JavaScript security workflow for a fresh installation, the 31-case security module, browser cases, shared coverage, Storybook build, complete npm audit output, and evidence upload. The gate fails critical npm findings; it does not reinterpret the remaining 133 findings as absent. Existing broader test and security policies are not changed by this evidence bundle.

    artifact-manifest.json maps each retained artifact to its original local source, byte count, and SHA-256. The original Trivy receipts also record scanner commands, database identity, input hashes, and output hashes. The large database itself and generated build directories are not committed. Raw .log files are retained byte-for-byte, including their original trailing whitespace and blank final lines; their recorded hashes must not be normalized. The earlier unstaged git diff --check did not inspect these then-untracked artifacts. The staged source/documentation whitespace check passes when the raw logs under this evidence directory are explicitly excluded; an unrestricted staged check reports the preserved log whitespace. Validate the source manifest against the candidate before applying these results to a later source revision. No Python policy, uv.lock, Flutter configuration, deployment, or frontend test-contract implementation is changed by this JavaScript repair.
